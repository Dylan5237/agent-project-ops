# APO v0.3.1 — 远端检查、日志脱敏与恢复保全

本补丁修复 v0.3.0 的四项边界缺陷。比较基线是正式 v0.3.0 提交 `8347c02008562d4cdf65cd3c7c07130ba9b8643a`。规则原则保持不变，PRINCIPLES 的规则版本仍为 v0.3.0。

本文随候选 PR 提供。只有获批合并、发布工作流完成，并核对 [v0.3.1 正式发行页](https://github.com/Dylan5237/agent-project-ops/releases/tag/v0.3.1)、标签提交与附件校验后，才能使用本版升级业务项目。候选检查通过不代表正式发行或最终验收完成。

## 修复了什么

1. **开任务和收尾先检查远端，错误就停。** `new-worktree.sh` 与 `tidy-worktrees.sh` 共用硬检查：只能有 GitHub `origin`，登记只能授权 origin，全部实际 fetch/push 地址（含多个 pushurl 和 URL 重写）必须属于同一安全 GitHub 仓库。异常在首次传输和本地动作前非零退出；开任务不会把收尾脚本的远端拒绝当作警告后继续。后续传输、工作区动作和保存任务起点前也会重检。
2. **盘点日志不再输出远端 URL。** 独立安装的 `repo-reconciliation-cleanup` 盘点脚本只输出远端名称及 `SAFE_GITHUB` / `REVIEW_REQUIRED` 分类；可疑名称使用固定提示，Git 查询错误中的 URL 和凭据也不回显。分类只说明本地 URL 元数据，不能当作写权限、网络可达或验收结论。
3. **技能副本恢复资料可跨任务工作区退役保留。** `sync-skills` 将旧目录和 manifest 放在 Git 公共目录的唯一 `apo-skill-sync/<id>/` 下，避免 linked worktree 退役时丢失恢复资料。写入前拒绝链接、junction 或跨卷恢复路径，保留预览、精确 plan_id、同卷移动和失败回滚。
4. **轻量档按任务启动。** 初始化指引按已选档位分流：light 创建自带合同的首个任务，不要求 Phase；standard（包括未记录档位时）仍创建 Phase。两档都明确登记总控台的兼容索引，确保状态可生成；先冻结、执行大改动检查，命中时等待覆盖范围的开工批准。最终验收和发布确认要求不变。

## 新增与删除

新增对应的隔离回归和两档离线初始化演练，覆盖错误远端零传输/零改动、秘密哨兵双流脱敏、真实临时工作区退役后恢复、跨卷零写及档位指引。离线演练不代表真实 Agent Host 已验收。

本补丁没有新增功能删除或远端渠道。v0.3.0 已删除的 GitLab 等分享/导出、Fleet 登记表、Cursor/Copilot/Continue/Aider 规则模板和独立中文版文档仍不恢复；从 v0.2.1 升级请同时审阅 [v0.3.0 变化清单](https://github.com/Dylan5237/agent-project-ops/blob/v0.3.0/docs/releases/v0.3.0.md)。

## 已有项目升级时要注意

- **硬检查可能暴露旧配置。** 本版不会自动移除额外远端、pushurl、URL 重写或旧角色。检查不通过时先记录配置问题，按该项目的迁移授权处理；不能靠关闭 hook 或改用其他远端继续。正常 GitHub origin 的开工/合并/保全流程保持原有语义。
- **先保存旧恢复资料。** 旧版 linked worktree 私有 Git 目录内的同步备份不会自动迁入公共目录。在退役旧工作区前，按旧 manifest 保全所需资料。新路径能跨 linked worktree 退役保留，但仍随整个仓库的公共 Git 目录存在，不是外部灾备。
- **跨卷恢复会直接拒绝。** 新版在创建恢复目录和 staging 前检查目标及其父目录所在卷；不能安全使用同卷移动时不应用，不自动改成复制/删除。按输出的 manifest 恢复时，先将当前副本移到保留位置，再将编号旧树移回原目标。
- **仍须审批具体升级计划。** 从正式版本的可信完整历史，在隔离工作区生成新 `plan_id`，核对文件改删、自有规则、项目设置和控制面待办后申请批准；不复用其他版本的计划或只改 PIN。本版不会批量更新业务项目，也不会清理旧任务目录。
- **回退依照实际状态。** 未提交且反向检查通过的纯升级补丁可反向应用；提交/合并后走普通回退 PR。恢复目录按其 manifest 使用，文件回退不自动回退 GitHub 状态；不移动或覆盖正式标签。

## 发行与验证边界

既有发布触发和权限不变；批准后普通合并 VERSION 变更，主线检查成功才发布新标签。附件仍为 `apo-v0.3.1.tar.gz`、`apo-v0.3.1.zip`、`RELEASE_SHA.txt`、`SHA256SUMS`、`UPGRADE.md` 共 5 个。核对标签提交等于 `RELEASE_SHA.txt`，并按 `SHA256SUMS` 检查另外四个文件；旧标签和附件保持原样。

实际测试结果和逐条审查处置以候选 PR 的当前提交及 CI 为准。测试覆盖隔离 Git/文件系统和文档契约，不代表任意宿主、业务升级或 GitLab 发布已验收；权限、ACL 等全部系统属性仍不在技能同步复制范围内。发布须另批，#110 最终验收也由拍板人决定。
