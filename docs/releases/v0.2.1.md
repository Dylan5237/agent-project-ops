# APO v0.2.1 — 恢复 URL + 简短提示词的默认使用入口

本补丁版延续 [v0.2.0](./v0.2.0.md) 已发布的初始化、受控旧规则升级、GitHub 控制面、工作区和只读诊断能力，不更改十项治理不变量。

## 用户推荐用法（保持兼容）

直接在有 GitHub 访问和本地 Git/文件系统能力的 Coding Agent 中发送以下一句，不要求预装 Skill 或记忆 CLI：

```text
使用 https://github.com/Dylan5237/agent-project-ops 初始化当前项目。
使用 https://github.com/Dylan5237/agent-project-ops 更新当前项目的apo规则。
```

Agent 应在具备相应工具时核实最新**已发布的稳定 Release**及其精确提交 SHA，读取对应 Skill 和 Playbook。初始化须按目录现状路由 Bootstrap 或 Adoption；已绑定旧版的项目执行安全 Upgrade，不覆盖自定义项目规则；只读预览后需单独确认升级 `plan_id` 才能应用 Git 补丁。

## 改动与限制

- #89：在中英 README、快速上手、升级指南中将两句提示词提升为首要入口。
- `bootstrap-project`、`upgrade-project` 的 Skill 描述直接匹配原中文 URL 命令，说明稳定版来源、项目状态路由与权限边界。
- 新增 `tests/short-prompt-contract.sh` 防止未来文档和 Skill 触发说明偏离；发行验证继续包含 Python 升级正反例及 Linux/macOS/Windows 的 v0.1.2 真实迁移回归。
- 本版**没有**增加通用 Agent Runtime、宿主内置 URL 拦截器或 UI。若 Coding Agent 无网络、Git、文件系统或 GitHub 权限，它必须说明阻塞；静态合同 CI 不能替代任意宿主端到端用户体验验收。
- #74/#75 原自然语言三旅程实验仍不在本版范围。本补丁不自动修改任何业务仓、不倒签历史冻结与验收、不取消项目实际批准的权限/评审政策。

## 发行和升级来源

仅以 GitHub `v0.2.1` 正式 Release 和其经 CI 验证的精确 SHA 为准，不以候选分支或漂移的 `main` 冒充已发布版本。升级旧项目请使用 [中文指南](../UPGRADE.zh-CN.md)，先在隔离 Worktree 预览、确认 `plan_id`、应用/回退，再按本项目权限协调 GitHub Command Center 和 PR。
