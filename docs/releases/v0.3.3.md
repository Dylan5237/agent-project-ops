# APO v0.3.3 — 推送前统一校验单远端与登记

本补丁修复 pre-push 在 origin 地址合法时仍允许额外远端、旧格式登记或镜像配置推送的缺口。比较基线是正式 v0.3.2 提交 `fcbb1f32f75dd0c63c39bd137b4d528514d537a3`，实现及回归见 [PR #117](https://github.com/Dylan5237/agent-project-ops/pull/117)。PRINCIPLES 的固定规则版本仍为 v0.3.0。

使用前核对 [v0.3.3 正式发行页](https://github.com/Dylan5237/agent-project-ops/releases/tag/v0.3.3)、标签提交和附件校验。PR 检查通过不代表正式发行已完成。

## 修复内容

1. **推送前执行完整权限自检。** canonical hook 复用现有 `github_worktree_authority`：只支持一个名为 origin 的远端、唯一有效的 `authority=origin` 登记，以及未启用镜像的 origin。已有 origin 地址与实际推送目标必须仍属于同一受支持的 GitHub 仓库。
2. **旧格式登记不能放行。** 额外的 projection、share_export 等行即使为空或 `(none)`，也会被拒绝；重复、未知、缺失登记同样失败闭合。合法登记允许注释、空行和 CRLF 换行。
3. **hook 拒绝信息不回显原始地址。** Git 传入的远端名称可能是原始 URL，因此只输出固定拒绝原因；Git 自身的传输日志不属于本 hook 的输出范围。

## 行为与验证边界

- 保留首次推送、真实远端默认分支查询、禁止直接修改/删除默认分支、项目设置检查及实际推送 URL 校验。
- 正向测试夹具改为合法 origin-only 配置；负向用真实 `git push` 和隔离 bare 仓库验证，必须由 hook 拒绝且全部目标 refs 保持不变。mirror 用例无显式 refspec 并包含实际更新，确保执行到 hook。
- 新测试先对旧 hook 复现失败，再验证修复。测试使用本地 fake SSH；未向真实业务仓库推送测试引用。CI 和自动审查以最终发行提交为准，不代替人的业务验收。
- 客户端 hook 可以被绕过，服务端仓库保护仍是最终防线；不能使用绕过手段规避项目规则。

## 已有项目升级

- 使用官方干净完整历史克隆和正式 v0.3.3 标签，保持 `PYTHONDONTWRITEBYTECODE=1`，在独立升级分支重新预览；不能只改 PIN 或重新应用已经执行过的旧计划。
- 旧格式 remotes 的自动规范化仍未实现，升级预览保留原登记。需要规范为一行 `authority=origin` 的项目，应单独审阅并按项目规则授权这项修改，在正常推送前完成；它不会自动出现在升级补丁的改动清单中。
- 额外远端或非空旧角色仍须先由项目迁移决定处置，不能静默删改配置来通过自检。doctor 对旧格式的通过结果不能代替严格登记检查。
- 按既有升级流程核对新的 `plan_id`、源提交、目标目录与分支、全部改动/删除路径和项目设置；计划或批准范围发生变化时重新审阅，未批准时只预览，不导出或应用补丁。
- 从旧版升级仍可能删除已退役的投影/分享 helper 和未选择的工具适配；应核对外部自动化依赖。本版不新增 GitLab 或同事分享渠道。

## 发行与恢复

发行工作流、触发条件和权限保持不变；VERSION 改动经正常 PR 合并到 main 后才触发正式发布。附件为 `apo-v0.3.3.tar.gz`、`apo-v0.3.3.zip`、`RELEASE_SHA.txt`、`SHA256SUMS`、`UPGRADE.md`，共5个。

核对 tag、Release 目标、`RELEASE_SHA.txt` 与精确发行提交一致，验证 GitHub digest 和 `SHA256SUMS`，再核对两种归档逐文件对应 Git blob。已有正式标签及附件不覆盖，后续恢复走普通回退 PR。
