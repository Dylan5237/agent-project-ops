# APO v0.3.2 — 校验任务退休的 PR 来源与当前提交

本补丁修复任务退休可能误用同名 fork 或历史已关闭 PR 的问题。比较基线是正式 v0.3.1 提交 `e5becf09a19a2a30d0a3344a0ccc0548bd471733`，实现见 [PR #113](https://github.com/Dylan5237/agent-project-ops/pull/113)。规则原则保持不变，PRINCIPLES 的规则版本仍为 v0.3.0。

使用前核对 [v0.3.2 正式发行页](https://github.com/Dylan5237/agent-project-ops/releases/tag/v0.3.2)、标签提交与附件校验。PR 检查通过不代表正式发行已经完成。

## 修复内容

1. **同名 PR 必须属于当前仓库。** 退休脚本核对 PR head 仓库、owner、分支及跨仓标记，fork 的同名 CLOSED 或 MERGED PR 不能作为 origin 任务的退休证据。
2. **已关闭 PR 必须精确对应当前任务提交。** CLOSED PR 的 head 只有等于当前 tip 时才允许先推送归档标签再退休。旧 PR 关闭后继续提交、复用分支名或更换为无关提交时，保留当前工作。
3. **证据不完整时保留。** 来源、分支或提交信息缺失，以及查询达到20条上限、可能漏掉后续 OPEN PR 时，不自动退休；显式 `--abandon` 也不能绕过未知 PR 历史的保护。可信同源 OPEN PR 继续优先保护。

## 行为与验证边界

- 保留现有 CLI、默认只读报告及 `apo-tidy:` 摘要格式；合法 MERGED/squash、匹配 CLOSED 的归档退休和未提交、忽略文件保护仍有效。
- 刚好20条且实际已经完整的历史也会保留，需要另行核对；本次未加入分页能力。
- 新增实际脚本回归，覆盖 worktree、本地仅分支和远端仅分支，对误匹配场景检查目录、文件、引用及归档标签不被改变；旧版可复现错误清理计划。
- 使用隔离本地 bare 仓库和受约束的测试传输层，不代表已在真实 fork 上执行破坏性清理。测试结果与自动审查以本版最终提交及 CI 为准，不代替业务项目验收。

## 已有项目升级

- v0.3.1 项目也需要重新预览，才能获得修复后的脚本。使用官方干净完整历史克隆、正式标签和精确提交，保持 `PYTHONDONTWRITEBYTECODE=1`。
- 此前批准的计划不会自动覆盖本版。重新核对设置、路径、内容指纹及删除文件，按项目已有批准规则取得新计划授权；不只改 PIN，不在未批准时应用补丁。
- 旧格式 remotes 仍需单独规范为一行 `authority=origin`；本版没有加入自动规范化。额外远端或非空旧角色仍需项目迁移决定，不静默移除。
- 从旧版升级时仍会删除已退役的分享/投影及未选用工具适配。特别核对外部自动化对旧 helper 的依赖；本版不新增 GitLab 或其他发布渠道。
- 合并后同步控制面并在真实主检出执行只读 tidy。计划中其他旧分支和目录的删除须按既有范围另行处置，不因报告通过自动获批。

## 发行与恢复

发行触发、权限及制品种类保持不变；只有 VERSION 改动合并到 main 才触发正式发布。附件为 `apo-v0.3.2.tar.gz`、`apo-v0.3.2.zip`、`RELEASE_SHA.txt`、`SHA256SUMS`、`UPGRADE.md`，共5个。

核对标签提交与 `RELEASE_SHA.txt`、Release 目标一致，检查 GitHub digest 和 `SHA256SUMS`，并确认压缩包对应精确源树。旧标签及附件不覆盖。

本版同时把发行标题改为通用版本标题，README 使用当前说明和最新正式发行入口。没有修改规则原则版本、业务代码或业务依赖。提交后的恢复走普通回退 PR；已有正式标签不移动。
