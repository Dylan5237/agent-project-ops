# APO v0.3.0 — 简化规则、按需初始化与自动化

这版把相对 v0.2.1 已完成的规则、初始化、任务派发和自动化改造打成一个发行包。主要变化是：只支持 GitHub 主仓，减少重复规则和人工维护，并把每次需要你决定的事集中说清楚。

比较基线是正式标签 v0.2.1 的实际文件（提交 `a700a6153ad0a2130be3d98bc505b22160ab3434`）；原则文件里的规则版本变更记录不等同于包的正式发行历史。

本文是随发版 PR 提供的变更清单。正式发布是否完成，以 [v0.3.0 发行页](https://github.com/Dylan5237/agent-project-ops/releases/tag/v0.3.0)、标签提交和附件校验为准；PR 检查通过、版本号改变都不能代替正式 Release，更不能代替阶段最终验收。

## 相对 v0.2.1 新增了什么

- **规则分层，确认次数更明确。** 区分不能关闭的底线、初始化时选择的项目设置和每次改动的判断；大改动开工、最终验收、例外由拍板人决定，其余由主 Agent 推进。新增固定的决策请求和结果记录格式，可以提前批准写明的后续阶段，最终验收仍须单独进行。
- **轻量和标准两种流程。** 轻量档按任务推进、发布前集中验收；标准档按阶段验收。两档遵守相同底线和大改动清单，未记录时使用标准档。
- **初始化先选再生成。** 明确选择流程档位、使用的 Agent 工具和可选外部工具；按选择生成文件。支持的 Agent 工具为 Codex、Claude Code、WorkBuddy；Arckeep、Grok Bot 作为可选接入，不再成为通用流程依赖。
- **规则只维护一份。** AGENTS.md 保存规则正文，CLAUDE.md 只保留一行 `@AGENTS.md` 导入；技能正本放在 `.agents/skills/`，按选择复制到 `.claude/skills/`、`.codebuddy/skills/` 并检查一致性。
- **任务交接有统一格式。** 新增任务单、认领/开工、完成回报模板，以及执行 Agent 专用技能。认领不等于开工，交付不等于验收；主 Agent 自己实现的任务仍等拍板人最终验收。
- **总控台状态先预览再写入。** 脚本读取 GitHub 状态和正式决策，生成总控台第 1 节；主 Agent 核对后按同一计划摘要写入，其他章节保持原样。叙述性进展仍由主 Agent 提供，不由脚本判断验收。
- **派发前提示文件冲突。** 按任务声明的文件/目录范围比较同批候选和其他活动任务；发现重叠或范围不明先停，不把检查当作自动派发或文件锁。
- **技能副本一条命令同步。** 默认展示差异；确认计划摘要后，只同步已选宿主的副本。过期计划和链接越界会拒绝写入，旧目录及多余内容保留恢复副本。
- **工作区自动收尾。** 单任务可复用空闲主检出，并行任务受工作区数量上限约束；合并或有存档证据的工作由脚本退休，脏、未合并和无法核实的工作保留。推送守卫读取远端真实默认分支；收尾无法快进更新时明确报错并返回失败，不静默成功。
- **修复生成技能的三个失效链接。** bootstrap-project 改为链接到随项目复制的现行原则和初始化手册，不再依赖没有复制的历史 RFC/ADR。

以上是 v0.2.1 以来的累计变化。发版 PR 本身只调整版本、发布/使用说明和旧版本断言，不在本次新增这些运行时功能，也不修改 PRINCIPLES。

## 删掉了什么

| 删除或不再要求的内容 | 现在怎么做 |
| --- | --- |
| GitLab 等其他远端的分享/导出、projection/export/share-export 技能、手册与脚本 | 只支持 GitHub `origin`。没有随本版提供新的内网发布渠道；旧远端配置不会被自动删除或迁移 |
| 方法论仓库自己的 Fleet 登记表与自我试用的 Fleet/晨报指针 | 状态留在项目自己的 GitHub 总控台。v0.2.1 已不要求普通项目登记到作者的个人 Fleet；本版继续清理仓库自身的残留，历史记录保留 |
| Cursor、Copilot、Continue、Aider 规则模板和适配入口 | 初始化不再生成这些模板；本版按已选的 Codex、Claude Code、WorkBuddy 布局生成 |
| 必须另开一个“证据 PR”的要求 | 证据可直接放在实现 PR 或 Phase Issue；大型材料仍可自愿单独开 PR |
| 单独维护的中文版 README、快速上手和升级文档（`.zh-CN.md`） | 保留的 `README.md`、`docs/GETTING_STARTED.md`、`docs/UPGRADE.md` 统一用中文；不是删除中文内容 |

v0.2.1 已取消通用 Cursor Bugbot 依赖，本版不把它重复计作新增删除项。Grok Bot 的可选接入属于上面的新增内容；项目已批准的实际审查门禁继续有效。

历史 ADR、RFC、发布说明和验收证据保留，用来解释过去，不代表已删除功能仍受支持。

## 已有项目升级时要注意

1. **先盘点旧用法，不能直接覆盖。** 尤其检查 GitLab 分享/导出、额外 Git remote、退休 Agent 模板、Fleet 要求，以及项目自己追加的规则。旧导出角色仍启用或存在额外远端时，升级器会先停止；本版不会擅自关闭这些用法。需要先取得该项目的迁移决定。
2. **删文件要看具体计划。** 已知由旧版 APO 生成、且项目没有改过的退休模板或脚本，可能列入升级删除项；自己改过的文件会产生归属冲突，未知文件和业务文件不会因为同名工具退役就被扫删。逐文件检查实际 `plan_id`，不要把这份发行清单当成删除授权。
3. **补齐三项设置，保全自有规则。** 旧项目没有完整选择时，先明确流程档位、Agent 工具和外部工具。CLAUDE.md 有自有内容时，先按项目授权审阅并保全到 AGENTS.md，再改成一行导入；未知配置、旧 PIN 无法核实、脏工作区或规则冲突都要停止。
4. **来源必须是核验后的正式版本。** 使用干净、包含旧 PIN 的可信完整 Git 历史；发行压缩包本身没有升级所需的完整历史。先在隔离工作区预览，明确批准该 `plan_id` 后才导出和应用补丁；来源、基线、设置变化后原计划和批准不能复用。
5. **本地补丁不等于控制面已升级。** 另外核对 GitHub 总控台、活动 Phase 和项目专属政策，保留历史冻结与验收。移除 APO 通用要求不会自动撤销项目自己的审查、发布或 Fleet 约定，也不会自动更改外部登记。
6. **保留可复验的回退方法。** 未提交补丁只有在反向检查通过、没有混入其他改动时才能反向应用；提交或合并后走正常回退 PR。文件回退不自动回退 GitHub 状态，不能靠移动正式标签回退发行。

本轮发行只计划使用 **zentao-mcp** 做业务试点，其他项目本次不升级。发版先经单独确认；正式发行核验完成后才做试点只读检查和隔离预览，再按该项目的具体 `plan_id` 单独确认应用。发布这份说明不代表试点已经升级。

详细步骤见[升级指南](https://github.com/Dylan5237/agent-project-ops/blob/v0.3.0/docs/UPGRADE.md)，命令用法见[自动化手册](https://github.com/Dylan5237/agent-project-ops/blob/v0.3.0/playbooks/automation.md)。

## 发行附件与验证边界

既有发布工作流会在批准后合并 VERSION 变更、且主线检查成功时生成新版本，拒绝覆盖已有标签。附件共 5 个：

- `apo-v0.3.0.tar.gz`
- `apo-v0.3.0.zip`
- `RELEASE_SHA.txt`
- `SHA256SUMS`
- `UPGRADE.md`

核对标签指向的提交与 `RELEASE_SHA.txt` 一致，并按 `SHA256SUMS` 检查两个压缩包、提交文件和升级指南。v0.2.1 的旧发行及 6 个附件保持原样。

本版没有增加通用 Agent 运行时、后台派发服务或新的 GitLab 发布渠道。状态写入仍有 GitHub 并发窗口，文件冲突检查依赖任务声明；技能同步保留内容、目录和 POSIX 权限，不复制 owner/group/ACL 等全部系统属性。CI 和隔离回归只说明相应技术场景经过检查，不代表任意宿主或业务项目已经验收。
