# APO v0.3.4 — 完整权威校验、固定查询主机与 CRLF 诊断

本补丁修复控制面自动化漏检旧远端登记、工作区退休查询受 `GH_HOST` 影响，以及 Windows CRLF 项目数据的诊断误报。比较基线为正式 v0.3.3 提交 `0d20dbf55db410fd2ed901b2ddb595fbeacaf1bf`；实现及回归见 [PR #124](https://github.com/Dylan5237/agent-project-ops/pull/124) 和 [PR #123](https://github.com/Dylan5237/agent-project-ops/pull/123)。PRINCIPLES 固定规则版本仍为 v0.3.0。

使用前核对 [v0.3.4 正式发行页](https://github.com/Dylan5237/agent-project-ops/releases/tag/v0.3.4)、标签提交和附件。版本号或候选 PR 检查通过不表示正式发行已经完成。

## 修复内容

1. **控制面操作先校验完整权威。** `project-automation.py` 复用现有 `github_worktree_authority`，不再只验证 origin URL。额外远端、非规范或缺失的登记、符号链接登记，以及启用或无效的 mirror 配置都会在调用 GitHub API 前被拒绝；`status --apply` 不能从这些检出继续写总控台。合法的 GitHub origin 和规范登记继续可用。
2. **退休证据固定来自 github.com。** `tidy-worktrees.sh` 的 `gh repo view` 和 `gh pr list -R` 均显式传入 `github.com/owner/repo`，不因环境 `GH_HOST` 采用企业实例中同名仓库、分支和提交的 PR。内部身份比较仍使用 owner/repo；fork 来源、CLOSED 当前 tip 关联及离线降级规则保持。
3. **doctor 正确读取 CRLF 项目数据。** 逐行保留 PIN 和 authority 的原始字段，只移除一个行尾 CR；合法 LF/CRLF 均可诊断，内嵌 CR、双终止 CR、非法 SHA 或 authority 仍拒绝，PIN URL 中残留 CR 也拒绝。诊断不修改文件或 Git 配置，不回显原始私密 URL。

## 行为与验证边界

- Python 到 Git Bash 的真实边界回归覆盖额外远端、旧角色、缺失或链接登记和镜像配置；拒绝场景不调用 GitHub API。隔离的 `status --apply` 实际入口也验证了拒绝退出与零调用。
- GH_HOST 冲突夹具让企业实例持有同名、同 SHA 的 CLOSED PR，必须保留 GitHub origin 任务；同时保留 fork 同名、历史分支复用、CLOSED 精确 tip 和离线场景。删除及归档行为只在临时测试仓验证。
- doctor 回归包含 LF/CRLF 正例、非法 CR 负例、URL 哨兵不泄漏，以及 PIN/remotes 原始字节、Git config 和工作区状态前后不变。Windows 两种 core.autocrlf 的独立克隆通过正式诊断入口；脚本自身仍按仓库属性使用 LF。
- 代码检查不代替本人验收、服务器保护或正式发行核验。doctor 的服务器与控制面 UNKNOWN 保留，不能据此声称远端状态已验证。

## 已有项目升级

- 等正式 v0.3.4 发行及附件核验完成，再使用官方干净、完整历史克隆和发布标签；设置 `PYTHONDONTWRITEBYTECODE=1` 或使用 `python -B`，避免源目录缓存导致拒绝。
- 在独立升级分支重新预览，保留已完成升级的原提交，不重复应用旧补丁。核对新 `plan_id`、完整改动清单和三项设置；用户约定的对账指纹变化时重新请求批准，未获批准不导出或应用。
- 完整守卫会拒绝非规范旧登记，包括值为空或 `(none)` 的旧角色行。预览仍不会自动规范它们；需要规范为单行 `authority=origin` 的项目，继续使用单独审阅、批准的登记提交，不静默改 Git remote。
- 额外远端或有效旧角色须先按项目迁移决定处置。本版不新增 GitLab 投影、发布副本或同事分享渠道；被删除的旧 helper 依赖仍需独立评审。
- doctor 对旧格式登记的专门告警、升级时自动规范旧角色，以及 codex 分支的退休分类不在本补丁范围内。诊断通过不等于严格登记格式已合规；未知旧目录和引用继续保留。

## 发行与恢复

发行工作流和权限不变：只有 VERSION 变更经正常 PR 合并到 main 后才触发正式发布。附件为 `apo-v0.3.4.tar.gz`、`apo-v0.3.4.zip`、`RELEASE_SHA.txt`、`SHA256SUMS`、`UPGRADE.md`，共 5 个。

核对 main 发行提交、tag、Release 目标和 `RELEASE_SHA.txt` 一致；验证 GitHub digest、`SHA256SUMS` 与两种归档逐文件 Git blob/权限对应。既有标签和附件不覆盖，失败或结果不明先只读回读；后续恢复走普通回退 PR。
