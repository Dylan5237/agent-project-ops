# APO：用自然语言管理 AI 编程项目

无需先了解 Worktree、Issue、PR 或 CI。向支持 APO Skill 的 Agent 描述你想做的事，Agent 负责读取项目事实、执行必要的工程操作，并在真正需要你决策时询问。

## 场景一：让 APO 管理这个项目

> 用 APO 管理我正在开发的这个项目。

Agent 应先判断项目是空目录、已有仓库、已接入 APO，还是部分接入失败。确认必要的仓库可见性、权限与影响后，使用现有 bootstrap/adoption 路径。不能自动覆盖已有业务文件、创建未授权的公开仓库或假装初始化成功。

**你应该看到：** 具体变更、控制面位置、实际 A/B/C 保护能力、缺失条件、唯一下一步。

## 场景二：继续这个项目

> 继续这个项目，告诉我上次做到哪里，下一步该做什么。

Agent 应从 `AGENTS.md`、PIN、Command Center、当前 Issue/PR/提交和证据恢复真实状态，而不是要求你复制旧聊天。出现冲突时先说明，不擅自开工。

**你应该看到：** 当前目标、已经接受的成果、进行中的工作、未验证项、待你拍板的事项和下一步（附事实来源）。

## 场景三：检查这次开发是否完成

> 检查这次开发是否满足验收要求。

Agent 应逐项对照已冻结的验收条件，给出验证的 SHA、环境与证据。区分“已验证 / 验证失败 / 未验证 / 需要用户体验确认”。CI 全绿不等于产品满足真实需求，PR 合并也不等于 Phase Accept。

## 当需要你选择

例如一个仓库有多个可用工作分支，而项目没有记录任务基线：Agent 优先调用宿主原生选项工具，展示已核实的候选和推荐依据；没有工具时直接询问。选择可以限定本任务，或经明确同意后提交为项目默认设置。

APO 不会为每一步弹出问题，也不提供新的 Web/桌面控制台。没有交互条件的执行环境必须使用已批准的配置或明确参数；不能猜测危险操作。
